# v0.6.23

Supports recovery of existing gateways and workers that still save
`arizzi74/Codex-Telegram-Gateway` as their release repository, including managers
older than v0.6.21.

The current manager resolves that exact legacy name directly to
`arizzi74/MACT`, independently of GitHub redirects. It confirms the canonical
repository's immutable identity and keeps strict asset, workflow, source
repository and release-tag verification. Custom repository selections retain
their own policy, and historical releases retain their original signing identity.

The minimal compatibility release uses the same v0.6.23 binaries and unchanged
checksum manifest as MACT, with a separate attestation signed by the legacy
repository's release workflow. Older managers can therefore install the
bridge through their existing update schedule. On the next successful normal
update, the new manager saves MACT as the release source, even if the service is
already current. `--check` remains read-only. No enrollment is required, and busy
workers continue to defer updates.

The old repository freezes at this bridge; subsequent releases only need to be
published to MACT. Its README points source, issues and history to MACT, and its
installer and Pages paths forward to the canonical locations.
Recreating it replaces GitHub's old rename redirects. Older historical release
URLs at the legacy name are not guaranteed to be mirrored.

Existing commands, service names, paths, credentials, sessions, archives,
gateway URLs and installed web app identity are preserved. See the
[MACT migration guide](../mact-migration.md) for release validation and manager
recovery.
