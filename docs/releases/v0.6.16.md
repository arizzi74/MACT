# v0.6.16

Fixes file permission preservation in session archives and restoration. A worker
running with `umask 0077` could save a `0644` file as `0600` or a `0755` executable
as `0700`. The archive could be verified successfully, but optional project
cleanup then refused to delete the unchanged source because its permissions
differed from the backup.

Archive copies and restored files now receive their exact saved permission bits
through their open file descriptors. The worker's file-creation mask and private
staging directories remain unchanged. Permission changes during copying are
rejected; strict project matching, activity fences and protected paths remain
in force.

Regression tests reproduce the failure under `umask 0077`, cover restore and
replay, and retain rejection of changed contents, permissions and extra files.
The native Codex 0.163.0 worker gate checks all four loaded/unloaded and
legacy/paginated cases with readable files and executables, while verifying that
cleanup preserves parent and neighboring directories.

Pinned speech-model downloads in release CI now allow five retries, with a
15-second delay and a 300-second retry window, to recover from transient DNS or
download failures. HTTPS, TLS, exact size and SHA-256 checks remain enforced.

This release includes the archive fix prepared for v0.6.15, which was never
published because a transient DNS failure interrupted the Intel macOS speech
build.

Archives created by older releases may contain reduced permission metadata;
updating a worker does not rewrite those existing files automatically.
