# v0.6.19

Fixes archival of sessions containing Codex multi-agent v2 subagents. The
isolated restore check resumes the main conversation and reads every
descendant's metadata and bounded history, then repeats after an app-server
restart. Subagents can retain working directories below the project root.
Checksum, native identity, project scope and history checks must all pass
before project cleanup can begin.

The Web UI's **Bind Telegram bot** menu shows each bot's base display name
alongside its currently attached session, for example **EnkiCodex · Gym
Tracker**. Unassigned bots show `<no session>`. Labels update after session
renames and bot moves; `<no bot>` disconnects the selected session's bot.

Regression coverage includes a genuine native v2 child/grandchild tree in both
history formats, restart and credential-isolation checks, failure cases for
metadata and history reads, and desktop/mobile bot-binding flows. The native
release gate now includes the new subagent archive proof. A browser fixture
also waits for mock request handling before inspecting its recorded status.

Update the gateway and workers, then refresh the Web UI. A previous failed
archive attempt can be retried after its worker updates; this release does not
automatically retry archiving or remove the preserved project and archive.
