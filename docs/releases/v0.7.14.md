# v0.7.14

Screenshot and image paths written in inline code now open the Web UI's file
download dialog, including paths in saved Claude replies. Markdown image links
also use that dialog. Commands, fenced examples and unsupported URLs stay text;
rendering a file reference never downloads it automatically.

Final Telegram replies can attach local images referenced in Markdown links or
standalone inline-code paths. The gateway reads up to four images of 10 MiB
each through the existing worker file stream. It keeps each read bound to the
original final delivery, worker, session, runtime generation and Telegram
destination. Workspace, credential, symbolic-link and hard-link protections
remain enforced. PNG/JPEG images use Telegram photos when supported by its
geometry and size limits; other supported images use image documents. Sent text
and attachment chunks retain their existing delivery checkpoints.

Claude processes receive delivery guidance through an appended system prompt:
save generated files inside the project and return usable Markdown links,
including local screenshot references. Bot credentials stay on the gateway.

Validation covers binary transfer and authorization fences, multipart uploads,
document fallback, redirects and errors, Telegram ordering and retry
checkpoints, resumed Claude sessions and mobile/browser file dialogs.
