# v0.7.11

Claude Code sessions now support model, reasoning effort and native permission
selection from the Web UI status bar and Telegram commands. Choices come from
the installed Claude CLI, including resolved model identifiers and its advertised
reasoning levels. Custom model identifiers remain available. Session preferences
persist across reconnects and worker restarts without changing other sessions.
Changes require the selected session to be idle, and bypassing permission checks
requires confirmation.

Claude worker settings also include default reasoning effort and the runtime's
supported permission modes. Official Claude model aliases remain independent;
custom endpoints retain their configured alias mapping. Unsupported model/effort
combinations are rejected. When changing the inference account, save native
default reasoning first, then choose an effort from the refreshed catalog.

An optional Enterprise monthly member budget appears beside session cost in the
status bar and in `/status`. Configure the member ID and a separate Enterprise
Admin API key with `read:spend_limits` in the worker settings. MACT reads the
effective USD monthly limit and period-to-date spending, distinguishes zero from
unlimited, and clears failed or obsolete observations. The key remains private
on the worker and is never passed to Claude or saved in conversation history.
Live Enterprise billing requires an eligible account and configured Admin key.
See the [Claude worker guide](../claude-code.md) for setup and scope.

The curl bootstrap also handles temporary directories that block execution by
using a private directory in the installing user's home. It verifies the same
pinned installer bytes again after moving them and removes temporary files on
exit.

Validation covers the protocol, adapters, worker, gateway and Admin backend;
browser controls and responsive layouts; session isolation and persistence;
native capability discovery without inference; budget arithmetic, credential
boundaries and account-switch races; and the bootstrap's real noexec regression.
The normal complete release validation, package auditing and signed provenance
checks remain required before publication.

Release runner recovery recognizes the intentionally skipped installer-only
test job in a normal full release, while continuing to reject unrelated skipped
or failed checks.
