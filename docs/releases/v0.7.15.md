# v0.7.15

Screenshot paths in inline code now open the Web UI download dialog, including
paths in saved Claude replies. Markdown image links use the same dialog.
Final Telegram replies attach referenced local images after their text, using
the existing protected worker file stream. Up to four images of 10 MiB each
are supported; image documents preserve files that do not fit Telegram's photo
limits. Attachments retain their session and bot routing, authorization checks
and delivery checkpoints. Claude receives explicit guidance to save deliverables
inside its project and return usable file links.

The automatic `/tgupdateworkers` status monitor and `/tginstances` now label
Claude versions as **Claude Code**. Structured inventory also exposes the
agent kind and version, with Claude versions separated from Codex versions.
Update instructions and command descriptions cover both agents.

An open reasoning menu now refreshes when a delayed model catalog arrives for
Codex as well as Claude. Opening a menu before optional model discovery finishes
no longer leaves it empty after the catalog has loaded. A deterministic browser
test verifies this delayed response without submitting a setting or prompt.

Validation covers protected binary transfer, Telegram uploads and document
fallback, bot/session routing, authorization fences, upload retries, native
Claude guidance on new/resumed sessions, worker version labels and responsive
file download dialogs.
