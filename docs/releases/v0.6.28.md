# v0.6.28

Keeps Telegram progress visible after steering or answering a question, and
shows the public reason when a coding-agent turn fails.

- Once a queued Telegram steer has been processed successfully, the gateway
  removes the old temporary cards and reposts the latest hourglass followed by
  the latest tool call at the bottom of the chat. Later updates edit those new
  cards. Queue admission alone does not move them.
- Complete question answers receive the same refresh after worker confirmation.
  Partial answers keep their existing immediate refresh while the remaining
  questions are collected. Async answer results retain their active turn ID.
- Reposting waits for queued acknowledgements or voice transcripts and old-card
  cleanup. Duplicate results and gateway restarts do not create extra cards.
  Destination, visibility, runtime-generation and active-turn checks prevent
  stale results from moving another session's progress.
- Telegram turn failures now include the public explanation supplied by the
  coding agent, including cybersecurity notices and recovery links. Public
  messages are redacted before being bounded and split for delivery; private
  provider details are excluded. A generic failure remains the fallback when
  no public reason is available.
- Temporary retry notices, recovered notices and messages from other turns are
  not reused as failure reasons. Existing short command/RPC error handling is
  unchanged.

Focused validation covers real registry/sender delivery order, queued-response
retries, restarts, duplicate results, question-answer variants, native error
projection through the worker outbox, redaction and long-message splitting.
Targeted race checks and static checks passed.

Update both gateway and workers for the complete behavior. Workers update when
idle; active coding-agent work continues during the gateway deployment.
