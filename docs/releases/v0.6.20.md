# v0.6.20

Fixes Telegram messages failing with `stale_turn` after a worker or host
restart. The worker now commits the first fresh session snapshot together with
its gateway notification before making the session available for commands.
An interrupted turn no longer stays active in Telegram routing while the
worker already considers the session idle. Existing live turns and commands'
original runtime and turn targets remain protected.

Generic file attachments now support **20 MiB (20,971,520 bytes)** in Telegram
and the desktop and mobile Web UI. Image input retains its **10 MiB** limit.
Files keep the existing session `inbound/` destination and caption behavior.
The relay's bounded input and transport capacities accommodate the larger
base64 payload.

Workers advertise their file-size capacity. Older workers retain their 10 MiB
limit and return an update message for larger uploads instead of receiving an
oversized frame. A queued file rejected after a worker downgrade also reports
the failure once to its original Telegram chat and topic.

Regression coverage includes restart recovery, active-turn preservation,
transaction rollback, exact-size and oversized uploads, complete transport
round trips, legacy-worker compatibility, and desktop/mobile upload flows.
The maximum-upload test uses a bounded 30-second wait to accommodate the
larger payload under race instrumentation.

Update the gateway and workers, then refresh the Web UI to use 20 MiB uploads.
