# v0.6.30

Reduces the work required before a Web UI session becomes usable when switching
between active sessions, including sessions on different workers.

- The first recent-message page and latest-turn state enable the conversation
  controls. Additional recent entries and older turn dates load afterward,
  without replacing newer live output or changing the reader's position.
- Older runtimes read at most three source turns per fallback page instead of
  traversing up to 32 turns before returning. Continuation cursors preserve
  complete, ordered access to earlier messages, including across empty turns.
- Verified saved-message timestamps are indexed after the page is sent and
  update existing time labels in place. Optional work is bounded, cancellable,
  and fenced to its original session, runtime and browser connection.
- Independent browser sessions share worker admission rather than waiting
  behind another session's history read. Update and archive admission retain
  their exclusive safeguards.
- A bounded read-only SQLite WAL pool lets session inventory reads proceed
  during timestamp-index writes. Durable writes remain serialized, and the
  existing database format is preserved.
- Background browser reads leave capacity for interactive input. Switching
  sessions never replays submitted prompts.

Validation includes desktop and mobile browser checks, full worker and worker
database race suites, cross-worker isolation, partial and empty history pages,
live-output ordering, timestamp priority and scroll anchors, cancellation,
SQLite snapshot isolation, and update/archive fences. Regression checks also
reproduce the previous blocking behavior against the old implementations.

Update both gateway and workers for the complete improvement. Worker updates
wait for idle state; running coding-agent work continues during gateway updates.
