# v0.6.17

Adds generic file uploads to the desktop and mobile Web UI. Use the composer’s
**＋** button, drag and drop, or a supported clipboard to attach one file of up
to **10 MiB (10,485,760 bytes)**. PNG, JPEG and GIF images keep their existing
image-input behavior; other files show a filename and size preview.

The selected worker saves generic files in the session project’s `inbound/`
directory, creating it when needed. Filenames receive a sanitized basename and
unique suffix, and existing files are never overwritten. Empty files are also
accepted. Files are not executed or unpacked automatically.

- Without text, **Upload** saves the file and confirms its path without starting
  or steering a Codex turn.
- With instructions, the saved path is appended to the prompt. An active turn
  is steered; an idle session starts a turn. `/tgsteer` can send the file path
  to an active turn with or without additional instructions.
- A lost acknowledgment retains the upload identity for a manual retry. A failed
  prompt retains its confirmed file path, so retrying does not create another
  copy. Changing the session, runtime or project prevents stale-path reuse.

Uploads reuse the authenticated WebSocket connection, existing transfer byte
budgets, and the worker’s secured inbound-file publication code. A private local
metadata ledger binds each upload to its file content and exact session target;
it does not add a replayable command or Telegram result. Filesystem, native
session, archive and worker-update admission checks remain enforced.

Saved-path acknowledgments are correlated with the browser request and checked
against the exact worker-owned destination. Ordinary output retains secret
redaction. Attachment drafts remain in tab memory, are excluded from encrypted
text recovery, and are cleared on reload or sign-out.

Both gateway and worker must be updated. Older workers return an update
instruction while leaving the viewer connected. Refresh an existing browser tab
after the gateway update to load the new composer controls.

Regression coverage includes desktop and mobile browser flows, the exact size
limit, arbitrary bytes and empty files, retry and navigation races, changed
targets, authentication revocation, redaction and existing image behavior.
